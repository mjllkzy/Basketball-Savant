# Workflow Guardrails

ShotClock should stay clean, deployable, and reviewable even while Codex tasks and scheduled refreshes are running.

## Core Rules

- `main` must stay clean and deployable.
- Every task starts with `git status --short`.
- If any file is dirty before the task starts, stop and classify it before editing.
- Do not mix UI, news, roster, contract, and production data changes in one commit.
- Do not push or deploy without explicit approval.
- Failed automation must not dirty `main`.

## Dirty Repo Protocol

When `git status --short` shows dirty files:

1. List every modified and untracked file.
2. Explain whether each file appears related to the current task, generated by automation, stale leftover work, user-owned work, or unknown.
3. Preserve useful work on a scoped review branch before restoring `main`.
4. Only continue once the current task is separated from pre-existing changes.

Do not revert user work or generated work unless the user approves that cleanup.

## Branch And Worktree Lanes

Use one scoped branch or worktree per lane:

| Lane | Branch pattern | Purpose |
| --- | --- | --- |
| Feature/UI/code | `codex/feature-<topic>` | App code, visual polish, component cleanup, tests |
| News refresh | `codex/review-news-refresh-YYYY-MM-DD` | Generated `news.json` updates and news refresh tests |
| Roster refresh | `codex/review-roster-refresh-YYYY-MM-DD` | Current roster transaction ledger updates |
| Contract refresh | `codex/review-contract-refresh-YYYY-MM-DD` | Contract raw/deal data updates |
| Production data refresh | `codex/review-production-data-refresh-YYYY-MM-DD` | Masterfile/Postgres refresh artifacts and validation |

Recurring automation should run in a disposable worktree or a scoped branch, not directly on `main`.

## Auto-Commit Policy

Low-risk refreshes may auto-commit only when all of these are true:

- The work is generated data only.
- The output is limited to the expected lane.
- Required lane checks pass.
- `git diff --check` passes.
- The commit message clearly identifies the refresh type and date.

News-only generated refreshes are the safest candidate for auto-commit after checks pass.

The following require review before production deploy:

- roster transaction policy changes;
- cap, payroll, guarantee, or contract calculations;
- contract/parser logic changes;
- data-model changes;
- generated contract or roster data where source quality is uncertain;
- any mixed code and generated-data change.

## Required Checks

Run the smallest relevant set first, then broaden checks when the blast radius is larger.

| Lane | Required checks |
| --- | --- |
| News | `pnpm test src/lib/news.test.ts tests/news-refresh-cli.test.ts`; run the news refresh command when regenerating data |
| Roster | `pnpm roster`; `pnpm test src/lib/data/currentRoster.test.ts src/lib/db/playerContracts.server.test.ts` |
| Contracts | `python3 -m json.tool <contract-json>`; `python3 scripts/import_player_contracts.py --source <contract-json>`; `pnpm test src/lib/db/playerContracts.server.test.ts` |
| Production data | relevant refresh command from `docs/production-data-refresh.md`; smoke checks when Postgres is touched |
| UI/code | targeted tests for touched files; `pnpm lint`; `pnpm build` when route/component behavior could affect production |
| All lanes | `git diff --check` |

## Failure Recovery

Automation should fail closed:

- stop on the first failed check;
- leave `main` untouched;
- keep logs and generated output in an artifact or review branch;
- report the exact command that failed;
- avoid pushing or deploying failed output;
- require a human review before retrying high-risk roster, cap, contract, parser, or model changes.

If a local workspace becomes dirty from a failed run, preserve useful changes on a review branch, return to `main`, restore only the affected files, and confirm `git status --short` is clean.

## Commit Scope

Before asking for commit approval, show:

- `git status --short`;
- `git diff --name-only`;
- `git diff --stat`;
- tests/checks run and results;
- files intentionally excluded from the commit.

Commit only the files required for the approved lane.
